## Why

Mnemonic phrases are currently picked by word frequency and length heuristics (`internal/phrase` scoring), which produces word soup: "denuncia artístico insultar hormona". An offline experiment (see design.md) shows that semantic ranking over the embedded vocabulary produces memorable mini-scenes — "restaurante vegetariano almorzar siesta", "asesino cazar guarida homicida" — at near-zero runtime cost. The scoring quality is 3.4× better on average, the vocabulary already exists, and password entropy is unaffected because letters are drawn by CSPRNG before any word is chosen.

## What Changes

- Embed **semantic vectors** (fastText Common Crawl, quantized to int8, ~1-2 MB per language) for every word in the builtin word lists, generated by a maintainer-only `make embeddings` pipeline (network at build time only; runtime stays offline).
- New **anchored scoring** for phrases: `cos(noun1, verb) + cos(verb, noun2) + cos(adj, noun1)`, plus a **distance band** on `cos(noun1, noun2)` that rejects near-synonym mush ("titular oficial titular nombramiento") while allowing related-but-distinct scene pairs.
- **Exact top-K selection** per block (K ≈ 10, deterministic, with diversity so candidates differ in words), replacing single-pick scoring for semantic mode.
- **TUI candidate cycling**: the picker shows the best candidate and lets the user cycle the pool per block (Tab / Shift+Tab); the human is the final semantic judge — this also covers cases no automatic scorer can fix (garbage data, uncomfortable words).
- Switch builtin **phrase template** to `noun → verb → noun → adjective` (adjective last, tagged to the first noun): the noun-verb-noun trio is the coherent core and the adjective is an attached descriptor. BREAKING for the mnemonic format of builtin languages.
- **Fallback**: languages without embedded vectors (user-defined/customized) keep the current scoring behavior.
- **Curate word lists** flagged by the experiment: EN nouns contain proper nouns ("norway", "ben", "andrew") and EN verbs contain auxiliaries ("will", "should", "may"); ES has filler verbs ("ser", "haber") and particles ("porqué"). A **suitability pass** additionally purges distressing vocabulary (sexual aggression, gore, morbidity, hate, weapons, disease dread) from the generation blocklists and committed lists — phrases are meant to be memorized and must not evoke unpleasant imagery.

## Non-goals

- LLM-based re-ranking: possible future opt-in layer (local server like Ollama) on top of the candidate pool; not in this change.
- Shipping full embedding models or subword models (hundreds of MB): only vectors for embedded vocabulary words.
- Semantic scoring for user-defined custom languages (no vectors available offline).
- CLI-side cycling (`generate` prints the top candidate; cycling is a TUI affordance).

## Capabilities

### New capability: `semantic-mnemonics`

Embedded vectors, anchored scoring with distance band, exact top-K pool, template change for builtin languages, fallback rules.

### Modified capability: `cli-tui`

New requirement for cycling through the candidate pool in the interactive picker.

## Impact

- **Affected specs**: `semantic-mnemonics` (new), `cli-tui` (new requirement), `language-profiles` (builtin template values), `embedded-word-data` (new embedded asset kind).
- **Affected code**: `internal/worddata` (embeddings asset + loader), new `internal/semantic` (vectors, scoring, top-K), `internal/phrase` (semantic selection mode), `internal/profile` (builtin templates), `internal/tui` (cycling), `cmd/prepare-embeddings` (new, maintainer-only), `Makefile`, `data/{en,es}/embeddings.bin` (generated), NOTICE (CC-BY-SA attribution), word-list TSVs (curation).
- **Security posture unchanged**: letters come from CSPRNG before word selection; word selection strategy does not affect password entropy (the initials of all valid phrases cover exactly the letter space, so enumeration via phrases equals brute force over letters).
